# API Testing

Мои практические работы по тестированию API в Postman.

**Автор:** Ulugbek Zinatov  
**Инструменты:** Postman, JavaScript (тесты в Postman)

## Проект: AutomationExercise API

**Тестируемый API:** https://automationexercise.com/api_list  
**Статус:** в работе

### Запросы и проверки

| Метод | Endpoint | Что проверяю | Статус |
|---|---|---|---|
| GET | `/api/productsList` | код ответа 200, структура JSON, список товаров не пустой, время ответа | Запланировано |
| GET | `/api/brandsList` | код ответа 200, структура JSON, список брендов не пустой, время ответа | Запланировано |
| GET | `/api/getUserDetailByEmail` | ответ для существующего и несуществующего Email, код ответа, поля пользователя | Запланировано |

### Какие проверки пишу в Postman

- Код ответа (например, `pm.response.to.have.status(200)`).
- Наличие и тип обязательных полей в JSON.
- Время ответа.
- Негативные случаи: неверный метод, пустые и некорректные параметры.

## Как запустить коллекцию

1. Скачать файл коллекции из папки `postman/`.
2. В Postman нажать **Import** и выбрать файл.
3. Открыть коллекцию и запустить через **Run collection** (Collection Runner).

## Результаты

Будут добавлены после прогона: количество запросов и проверок, пройдено и не пройдено, найденные дефекты. Баг-репорты по API оформляю в формате [Bug-Reports](../Manual-Testing/Bug-Reports.md), в шагах указываю метод, URL, тело запроса и фактический статус-код.
